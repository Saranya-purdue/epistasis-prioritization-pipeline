# Genetic Architecture Simulation Framework

This module contains code for phenotype simulations designed to evaluate interaction-detection methods under controlled additive and epistatic genetic architectures.

The simulations generate quantitative phenotypes from genotype matrices while varying causal SNP complexity, additive-epistatic overlap, and nonlinear interaction structure. Across mixed additive–epistatic simulations, broad-sense heritability and the relative contributions of additive and epistatic components are explicitly controlled.

## Module structure

```text
simulation/
├── README.md
├── simulate1.py
├── run_simulation1.py
├── simulation2.py
├── run_simulation2A.py
```


## Input data

All simulations expect a genotype matrix in CSV format with:

- rows = individuals
- columns = SNPs
- values = genotype dosages or encoded genotype values

The first column should contain the sample identifier and is read as the dataframe index.

Before running a simulation, update the genotype path in the corresponding run script:


# Simulation 1: Sparse Cross-Subset Epistatic Architecture

## Overview

Simulation 1 generates quantitative phenotypes using a structured nonlinear architecture in which epistatic effects arise only from interactions between predefined subsets of causal SNPs.

For each simulation setting:

- \(N\) causal SNPs are randomly selected from the genotype matrix,
- the selected SNPs are partitioned into three subsets, `s1`, `s2`, and `s3`,
- epistatic effects are generated only from cross-subset interactions between SNPs in `s1` and SNPs in `s2`,
- marginal effects are generated from all selected causal SNPs in `s1`, `s2`, and `s3`,
- the final phenotype is generated by summing the marginal component, epistatic component, and Gaussian residual noise.

This architecture produces a sparse nonlinear phenotype while keeping the number of ground-truth interaction terms computationally manageable.

## Simulation design

Simulation 1 evaluates the following causal SNP counts:

```text
15
50
100
250
```

For all settings, broad-sense heritability is fixed at:

```text
H2 = 0.20
```

The fraction of genetic variance assigned to marginal effects is:

```text
rho = 0.05
```

The remaining genetic variance is assigned to epistatic effects:

```text
1 - rho = 0.95
```

Under the implemented subset construction, the causal SNP settings generate:

| Causal SNPs | True epistatic pairs |
|---:|---:|
| 15 | 9 |
| 50 | 36 |
| 100 | 64 |
| 250 | 100 |

## Files

### `simulate1.py`

Contains the core Simulation 1 functions for:

- causal SNP selection,
- genotype preprocessing and standardization,
- construction of `s1`, `s2`, and `s3`,
- generation of marginal effects,
- generation of cross-subset epistatic effects,
- phenotype construction,
- variance rescaling to match the requested genetic variance components.

### `run_simulation1.py`

Runs all Simulation 1 scenarios and saves scenario-specific outputs and a combined summary table.

## How to run Simulation 1

Update the genotype path in `run_simulation1.py`:

```python

```

Then run:


# Simulation 2: Overlapping Additive and Epistatic Genetic Architecture

## Overview

Simulation 2 evaluates mixed additive–epistatic architectures in which the additive and epistatic causal SNP sets are allowed to overlap.

For each simulation setting:

- a set of additive causal SNPs is selected,
- a separate set of epistatic causal SNPs is selected,
- the two sets overlap according to a predefined proportion,
- additive effects are generated as a linear combination of additive SNP genotypes,
- epistatic effects are generated from multiplicative SNP-pair interaction terms,
- additive and epistatic components are independently rescaled to their target variance contributions,
- Gaussian residual noise is added to generate the observed phenotype.

Simulation 2 contains two complementary interaction architectures:

- **Simulation 2A:** dense all-pairwise epistasis
- **Simulation 2B:** controlled sparse epistasis

Both architectures use the same causal SNP selection, additive–epistatic overlap, heritability, and variance-partitioning framework. They differ only in the number of ground-truth epistatic pairs retained.

## Shared Simulation 2 parameters

Both Simulation 2A and Simulation 2B evaluate the Cartesian product of:

```text
causal SNP counts:
15
50
100
250

overlap proportions:
0.30
0.50
0.70
0.90
```

This gives 16 scenarios for each architecture.

For every scenario:

```text
num_additive = N
num_epistatic = N
```
Broad-sense heritability is fixed at:

```text
H2 = 0.20
```

The fraction of genetic variance assigned to additive effects is:

```text
rho = 0.05
```

The remaining genetic variance is assigned to epistatic effects:

```text
1 - rho = 0.95
```

Therefore, the target phenotype architecture assigns:

- 5% of genetic variance to the additive component,
- 95% of genetic variance to the epistatic component.

Genotypes are standardized before phenotype generation.

# Simulation 2A: Dense All-Pairwise Epistasis

## Overview

Simulation 2A represents a dense epistatic architecture.

After selecting the epistatic causal SNP set, all possible pairwise multiplicative interactions among those SNPs are included in the phenotype.

The resulting numbers of ground-truth interaction pairs are:

| Epistatic SNPs | True epistatic pairs |
|---:|---:|
| 15 | 105 |
| 50 | 1,225 |
| 100 | 4,950 |
| 250 | 31,125 |

Simulation 2A therefore progressively increases both causal SNP complexity and interaction density.

## Files

### `simulation2.py`

Contains the shared Simulation 2 phenotype-generation functions, including:

- genotype standardization,
- selection of additive and epistatic SNP sets,
- controlled additive–epistatic overlap,
- generation of additive effects,
- construction of candidate epistatic SNP pairs,
- generation and standardization of interaction terms,
- variance rescaling,
- phenotype generation,
- calculation of realized variance components.

For Simulation 2A, all possible pairs among the epistatic SNP set are retained by setting:

```python
num_epistatic_pairs = None
```

### `run_simulation2A.py`

Runs all 16 dense Simulation 2A scenarios and saves scenario-specific outputs and a combined summary table.

## How to run Simulation 2A

# Simulation 2B: Controlled Sparse Epistasis

## Overview

Simulation 2B uses the same additive–epistatic causal SNP sets and overlap design as Simulation 2A but restricts the number of ground-truth epistatic interaction pairs.

Instead of including every possible interaction among the epistatic SNPs, a fixed number of unique SNP pairs is randomly sampled without replacement from the complete set of possible epistatic pairs.

The number of retained true interaction pairs is set equal to the component-specific causal SNP count:

| Epistatic SNPs | Possible pairs | Retained true pairs |
|---:|---:|---:|
| 15 | 105 | 15 |
| 50 | 1,225 | 50 |
| 100 | 4,950 | 100 |
| 250 | 31,125 | 250 |

Thus, Simulation 2B increases causal SNP complexity while preventing the number of true interactions from growing quadratically.

This provides a controlled sparse counterpart to the dense architecture in Simulation 2A.

For Simulation 2B, the shared phenotype-generation function is called with:

```python
num_epistatic_pairs = n_snps
```

The selected interaction pairs are sampled without replacement, ensuring that every ground-truth pair is unique.

Because only a subset of all possible interactions is retained, not every SNP in the predefined epistatic SNP set is necessarily represented in a ground-truth interaction. The simulation therefore additionally records the set of **active epistatic SNPs**, defined as SNPs occurring in at least one retained interaction pair.

## Files

### `simulation2.py`

The same core phenotype generator used for Simulation 2A is used for Simulation 2B.

The only difference is that Simulation 2B specifies a fixed value for:

```python
num_epistatic_pairs
```

rather than retaining all possible pairwise interactions.

### `run_simulation2B.py`

Runs all 16 controlled-sparse Simulation 2B scenarios.

For each causal SNP setting:

```python
num_epistatic_pairs = n_snps
```

so that the number of true interaction pairs is restricted to:

```text
15
50
100
250
```

# Comparison of Simulation Architectures

| Simulation | Architecture | Additive–epistatic overlap | Number of true interactions |
|---|---|---|---|
| Simulation 1 | Sparse cross-subset epistasis | Not applicable | 9, 36, 64, 100 |
| Simulation 2A | Dense all-pairwise epistasis | 0.30, 0.50, 0.70, 0.90 | 105, 1,225, 4,950, 31,125 |
| Simulation 2B | Controlled sparse epistasis | 0.30, 0.50, 0.70, 0.90 | 15, 50, 100, 250 |

Simulation 2A and Simulation 2B use the same causal SNP counts, overlap proportions, heritability, and additive/epistatic variance allocation. Their primary difference is therefore the **density of the ground-truth interaction architecture**.

# Reproducibility

All simulations use NumPy random number generators with explicitly defined seeds.

Different scenarios use different deterministic seeds so that:

- causal SNP selection,
- additive effect generation,
- interaction-pair selection,
- epistatic effect generation,
- and phenotype noise generation

can be reproduced exactly when the same input genotype matrix and seed are used.

# Notes

- Genotypes are standardized before phenotype generation.
- Zero-variance genotype columns are safely converted to zero after standardization.
- Interaction terms are centered and standardized before generation of the epistatic phenotype component.
- Additive and epistatic phenotype components are independently rescaled to their requested target variances.
- Simulation 1 uses structured cross-subset interactions.
- Simulation 2A uses all possible pairwise interactions among epistatic SNPs.
- Simulation 2B randomly retains a fixed number of unique interaction pairs from the same possible pair space.
- Ground-truth SNPs, interaction pairs, and their effect sizes are saved for downstream interaction-recovery benchmarking.
